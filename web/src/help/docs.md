# Documentation

Quiver builds API documentation from your collection: descriptions, requests, parameters, headers, bodies, code samples and saved examples.

## Write it

- Collection description: **Overview** tab in the collection.
- Folder description: **Overview** tab in the folder.
- Request description: **Docs** tab in the request editor.

All three use Markdown, including headings, lists, tables, code blocks and links. Parameter and header **Description** columns appear in the docs too.

## View it

Open the collection and choose the **Documentation** tab. The left side lists every request. Pick a language from **Code samples** to change every example at once.

## Publish it

1. Go to the collection's **Export & publish** tab.
2. Turn on **Publish documentation at a public link**.
3. Share the link. Readers do not need a Quiver account.

Public docs never include scripts, auth values or secret variables. Headers that look like credentials, such as `Authorization` or `X-Api-Key`, are masked. Turn the toggle off to unpublish.
